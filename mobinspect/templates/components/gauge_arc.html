{% comment %} Reusable 270° arc gauge (radial score meter). Pure CSS/SVG — no JS charting library, no per-value trig in the template: the pointer dot's angle comes from composing two CSS rotate() transforms (see #mi-chrome .mi-gauge-* in base/app.html), and the arc itself uses the pathLength=100 stroke-dasharray trick. Tick marks are fixed (angle is constant regardless of value) so their coordinates are hardcoded literals. Params: value — 0..100 (required) color — CSS color for the progress arc / dot / glow. For any security-score/severity use, ALWAYS pass `value|score_color` (requires `{% load mi_score %}` in the including template) — the one shared threshold source in mobinspect/MobInspect/templatetags/mi_score.py, so the same numeric score never renders a different color on different pages. A bare hex is only appropriate for a genuinely non-severity gauge (none exist yet). sub_label — small text under the number, e.g. "/ 100" or "% risk" size_class — Tailwind size classes for the SVG, default "w-36 h-36" animate — if True, wires the existing global counter() Alpine helper (the including page must already define/load it, as appsec_dashboard.html and analytics/dashboard.html do) Usage: {% load mi_score %} {% include "components/gauge_arc.html" with value=security_score color=security_score|score_color sub_label="/ 100" animate=True %} The fallback below is the theme-aware "unknown severity" gray (var(--score-unknown), same family as severity-unknown), NOT brand blue — brand blue must never stand in for an unset severity tier (a real bug this replaces: an uncalled `color=` previously silently rendered brand-blue, which reads as a false severity signal rather than "no color was supplied"). {% endcomment %}
